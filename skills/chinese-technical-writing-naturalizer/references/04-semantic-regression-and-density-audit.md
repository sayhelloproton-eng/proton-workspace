# Semantic Regression and Density Audit

## 改写后检查什么

重要改写不只比较字数。至少检查以下内容有没有丢失或被错误强化：

- 日期、数字、百分比、时延、容量和版本；
- URL、引用、代码、命令、inline code 和代码块；
- 缩写、产品名、接口名和英文术语；
- 当前实现、目标设计、失败状态和未知状态；
- 事实 / 推断 / 假设 / 建议 / 计划的强度；
- 失败条件、反例、例外和适用边界；
- 原文中真正解释“为什么”的因果桥梁。

## Density Audit

改写更短不代表更好。重点区分两类删除：

**应该删除**：重复结论、装饰性开场、空评价、同义反复、没有信息增量的总结。

**不应该顺手删除**：例子、反例、机制、失败条件、操作细节、证据来源、关键对比和权衡。

如果改写后的文章只剩结论，没有足够材料让读者自己复现判断，说明压缩过度。

## 脚本的角色

`scripts/audit_markdown.py` 可以机械比较 URL、链接、代码、数字、术语、代码块和部分结构信号。它只能作为 review aid：

- 检测到损失 → 必须人工复核；
- 没检测到损失 → 不能证明语义等价；
- 模板信号变少 → 不能证明文风更好；
- 不得把结果转换成 AI-authorship 或“AI 味分数”。
