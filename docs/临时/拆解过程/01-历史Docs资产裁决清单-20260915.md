## 1. 本轮目标

本轮只做一件事：给历史 `docs/` 中的全部资产确定去向，不在本轮重写正文，也不提前冻结新文档体系目录。

裁决只有三类：

- **A｜保留迁移**：内容本身仍有长期价值，后续迁入 `proton-workspace/docs` 的材料层；允许后续改名、聚合和清理旧语义，但不先丢失原始材料。
- **B｜吸收提炼**：旧目录或文章结构不再保留，只提取仍成立的知识、证据、失败经验和方法，再进入新的主题材料；提炼完成后删除原资产。
- **C｜直接淘汰**：重复、过期、旧治理、旧映射、旧运行记录、第三方镜像或已有正式真源替代的内容，后续直接删除。

-----------------

## 5. 关键语义边界

最终文档系统不再存在旧平台作为当前项目、平台、目录或知识主题。

旧名称若必须出现，只能用于说明真实历史，例如：

> ProFlow 第二阶段 / MVP 验证时期曾存在的一组中间实验与实现，后来被正式 ProFlow 架构吸收或替代。

因此后续迁移必须同时做到：

```text
不复制旧目录树
不建立本地文档 ↔ 飞书 ↔ 代码的一一映射
不重建 Platform Registry 式文档治理
不把历史方案包装成当前实现
不为了“完整”保存重复导航、模板、作品集和归档
```

4. **形成正式知识入口**：从已经迁入和提炼后的真实材料中选择成熟主题，不要求本地材料全部发布。
5. **发布飞书并回读**：使用现有 `feishu-knowledge-publish` Skill / Automation，发布前先解决其与最新“主题投影、非严格 1:1”原则的 drift。

完成判断不是“远端文件数量与本地相等”，而是：重要知识有 owner、成熟知识有正式入口、历史资产全部有裁决、没有重复真源、没有关键内容丢失。
