## 交叉审计中发现并即时修复的缺口

### 《上下文工程》

补入：

- Claim Strength：Current Fact / Accepted Decision / Target / Historical / Inference / Boundary 不能被 Context 编译抹平；
- Sensitivity / Redaction：真实信息也要按 Consumer 最小暴露，Secret 不进入 Context 正文；
- Output Contract / Stop Condition：与 Goal / Scope / Approval 一样属于压缩时必须保护的执行边界；
- Task / Role / Workspace / Execution Lane 隔离：不同运行世界不允许隐式共享 Context；
- 派生消费层 Source Version / Readback：执行过发布不等于真实渠道已经是这一版。

### 《知识资产治理》

新建正式 Owner，吸收旧 ARC-005 与 KNO-009 中原本没有当前 Owner 的稳定价值：

- Claim 类型与事实强度；
- Evidence 只支撑覆盖范围内的 Claim；
- Revision / Supersession / Retirement；
- Impact Review；
- Publication Eligibility；
- Source Version / Readback；
- Feedback 只产生 Candidate；
- Experience / Memory / Evidence / Knowledge 分离；
- 独立 Occurrence；
- Counter-evidence；
- Maturity 与 Lifecycle 分离；
- 轻映射、重提炼。

## 明确退休的旧平台设计

以下内容不进入当前推荐架构：

- 五个 Context 子领域必须物化为五个服务；
- 通用 Context Request / Package 大 Schema；
- Context Instance Store、Delivery Receipt、Context Delta Registry、Resume Token 平台；
- Knowledge Pack Publisher / Projection Registry；
- Platform Registry、稳定 Asset ID、完整 Relation Graph 作为所有文档的硬依赖；
- 自动 Memory 晋升、自动知识改写；
- Feishu / GPT Knowledge / RAG / 本地文档严格一一映射。

这些机制只有在多个真实消费者反复产生同一种维护压力时才重新评估。
