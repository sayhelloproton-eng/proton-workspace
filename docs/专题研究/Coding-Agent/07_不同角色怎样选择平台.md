# 不同角色怎样选择平台

> 唯一职责：把前面的平台区别转换成实际选择，不做统一排行榜。

## 只想提高开发效率

### 更依赖 IDE 内持续协作

优先看 Cursor。

原因不是“模型最好”，而是 Human-Agent interaction、Editor Context、Diff / Review 工作流成熟。

### 更希望把完整任务交出去

优先看 Codex。

关注 Task、隔离执行、后台/云端任务、并行委派和最终 Review。

## 想把团队工程经验编进 Agent

优先研究 Claude Code。

重点不是日常使用，而是学习：Skill、Subagent、Hook、MCP、Project Instruction、Permission 怎样一起构成工程 Harness。

## 想自己掌握 Agent Stack

优先研究 OpenCode。

适合 Provider routing、私有模型、Runtime 插件、Agent / Tool 解耦，以及平台级二次开发。

## 想做跨平台 Skill / Plugin

不要押一家平台，建议建立四角实验场：

```text
Claude Code
→ Rich Harness / 源范式

OpenCode
→ Runtime Ownership

Codex
→ Task / Worktree / Cloud Delegation

Qwen Code
→ Compatibility / Portable Core 验证
```

## 想研究长期自主开发

Qoder 值得重点验证，但需要真实长任务 Eval，而不是只看宣传 Demo。

## 企业场景

国内企业可重点观察 CodeBuddy / WorkBuddy；如果核心诉求是基础设施控制、模型自由度和工程治理，则应把它和 OpenCode、Cursor、Claude Code 等放在同一责任框架下比较。

## 一个通用选型公式

选择平台时固定回答：

1. 我的主要工作对象是 Editor、Task、Runtime、Spec 还是 Organization？
2. 人要不要持续留在 Loop？
3. 任务需要多长生命周期？
4. 我是否需要拥有 Model / Provider / Runtime？
5. 我需要的是 Portable Skill，还是平台专属 Rich Capability？
6. 最终如何验证任务真的完成？

如果这六个问题没有答案，平台选型很容易退化成品牌偏好。
