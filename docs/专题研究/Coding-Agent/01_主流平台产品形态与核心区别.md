# 主流平台产品形态与核心区别

> 唯一职责：比较主流 Coding Agent / Agent Workspace 产品到底把什么对象放在产品中心。

## 先别按“功能多少”比较

同样支持 Agent、MCP、Skill 或 Background Task，并不意味着产品形态相同。更稳定的比较方式是看平台首先围绕什么组织工作：Editor、Task、Runtime、Spec、Repository 还是 Organization。

## 产品中心对照

| 平台 | 当前更像什么 | 核心中心 | 主要区别 |
|---|---|---|---|
| Claude Code | 可编程 Coding Harness | Agent + Engineering Rules | 把 Skills、Subagents、Hooks、MCP、Permission 等编进工程执行方式 |
| Codex | 任务委派与执行系统 | Task + Delegation | 强调独立任务、隔离工位、后台/云端执行与多任务监督 |
| OpenCode | 开放 Agent Runtime / Harness | Runtime + Ownership | 更强调模型、Provider、Agent、Plugin、Tool 的可替换和用户控制 |
| Cursor | AI IDE | Editor + Agent | 人长期留在编辑器里，与 Agent 高频交互、Review 和修改 |
| Kiro | Spec-driven 开发产品 | Intent / Spec | 强调先把需求、约束和计划显式化，再执行 |
| Qoder | 长任务 Coding Agent 平台 | Long-running Task | 更强调长任务持续推进、Cloud Agent / Task 交付 |
| Qwen Code | 开放兼容型 Coding Harness | Runtime + Compatibility | 重视吸收 Claude/Gemini/开放规范生态资产，适合兼容实验 |
| CodeBuddy / WorkBuddy | 企业 Agent 产品族 | Organization + Agent | 更强调组织使用、企业接入、Claude 生态兼容和托管能力 |
| TRAE | Code / Work 双工作形态 | Work Mode | 从 Coding 向 Work / Design 等复杂任务产品化延伸 |
| GitHub Copilot | GitHub 原生 Agent 层 | Repo / Issue / PR / CI | 最大差异是直接建立在 GitHub 协作真值和研发生命周期上 |

## 产品族不要混写

### OpenAI

应理解成：

```text
ChatGPT
├─ Chat
├─ Work
└─ Codex
```

Work 面向更广的长期、多步骤工作；Codex 聚焦软件与技术任务。不能把 Codex 等同于 ChatGPT 全部 Agent 能力。

### Anthropic

```text
Claude
├─ Chat
├─ Cowork
└─ Claude Code
```

Claude Code 是 Coding Harness；Cowork 是把 agentic work 扩展到更广工作对象。不要把 Claude Code 直接写成 Claude 全产品。

### 腾讯

CodeBuddy 不是简单“改名成 WorkBuddy”。更准确的理解是 CodeBuddy、WorkBuddy、Managed Agents 等形成一组企业 Agent 产品能力。

### Qoder / TRAE

两者都已经不能只按“IDE”理解：Qoder 正在向 Task / Work 方向扩展；TRAE 则明确存在 TraeCode 与 TraeWork 等不同工作形态。

### OpenCode

OpenCode Core 与 Oh My OpenCode（OMO）必须分开：前者是 Runtime / Harness，后者是其上的第三方增强体验与编排层。

## 最重要的比较结论

```text
Claude Code → 怎么把工程经验编进 Agent
Codex       → 怎么把完整任务委派出去
OpenCode    → 怎么拥有和改造自己的 Agent Runtime
Cursor      → 怎么让人和 Agent 在 IDE 内持续协作
Kiro        → 怎么用 Spec 收紧 Intent
Qoder       → 怎么推进长任务自主交付
Qwen Code   → 怎么吸收跨生态能力
GitHub      → 怎么把 Agent 接进真实研发协作生命周期
```

所以“谁最好”没有稳定答案；先看你希望优化哪一个工作对象。
