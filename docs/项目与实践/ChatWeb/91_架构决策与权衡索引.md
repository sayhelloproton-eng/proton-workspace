# 91｜架构决策与权衡索引

这里记录“为什么这样设计”的学习入口；正式裁决仍以 ChatWeb `docs/specs/08-decisions/` 与 Owner Spec 为准。

## S0｜产品与 Provider 基线

| ID | 决策 | 为什么 | 延后 / 拒绝什么 | 当前证据 |
|---|---|---|---|---|
| CW-DEC-001 | ChatWeb 独立于 ProFlow RAG | Chat 产品与知识构建的核心对象、生命周期和发布责任不同 | RAG 专用前端主流程 | S0 + S5 real integration |
| CW-DEC-002 | ModelProvider / ContextProvider 分离 | Streaming generation 与 bounded context read 的失败/取消语义不同 | 万能 `CapabilityProvider.execute()` | S0/S5 |
| CW-DEC-003 | Tool/MCP 单独执行边界 | Tool 可能有副作用、approval、幂等与多轮 loop | 把 Tool 塞进 ContextProvider | S8/S11/S12 F2 |
| CW-DEC-004 | Conversation + Message + ChatRun | 内容事实与一次生成尝试必须分开 | 只用 Message 表达 retry/error | S2～S12 |
| CW-DEC-005 | V0 不做 Branch Thread Tree | 当前只需要普通多轮聊天和失败 Retry | completed Regenerate / fork / answer branch | V0 scope |
| CW-DEC-007 | Runtime 拥有 Context composition | order/provenance/failure policy 是 ChatRun 编排责任 | Provider 自行决定整个 run | S5 Final |
| CW-DEC-008 | Provider discovery 可选 | OpenAI-compatible endpoint 不保证 model discovery | 伪造 `/models` 能力 | S3/S12 |
