## CW-S1-001｜漏掉真实部署环境导致错误 single-deployable 假设

- **现象**：S1-A 初版选择 Next full-stack single package，并计划 Route Handler 承载 Trusted Runtime。
- **漏项**：前端真实目标是 ChatGPT Sites + localhost；后端真实位置是本机 + tunnel。
- **根因**：deployment environment 没有作为架构一等输入。
- **纠偏**：Next frontend + Nest backend；ADR-003 superseded，新增 ADR-006；在任何依赖安装前完成。
- **防回归**：后续 framework/runtime 选型必须先列出部署位置、网络边界、secret ownership 与真实 consumer。

## CW-S1-002｜把执行 blocker 与产品兼容性分开

- **现象**：Sites Work quota=0，无法执行真实 build/version。
- **风险**：把外部额度阻塞误写成 Sites FAIL，或用理论文档替代真实 PASS。
- **纠偏**：保持 `BLOCKED_BY_WORK_QUOTA`，额度恢复后原地续接同一 Gate；最终真实 Version 1 PASS。
- **防回归**：external blocker、mechanical failure、product incompatibility 必须分开建模。

## CW-S1-003｜Sites static export 使 `next start` 失效

- **现象**：加入 `output: "export"` 后，`next start` 真实 exit 1。
- **根因**：部署 artifact 从 Next server runtime 变成静态 `out/`。
- **纠偏**：保留 `next dev`；production preview 改为锁定 `serve out`；Sites 与本地预览消费同一静态产物。
- **防回归**：部署适配改变 artifact shape 时，必须重新验证本地 dev/build/start 三条路径。

## CW-S1-004｜高可靠治理被执行成高频微观治理

- **现象**：S1 实际代码量不大，但 A～G 多个子门各自重复测试、Gate、文档写回和 Review，推进体感显著偏慢。
- **根因**：把 Stage 内子任务错误地当成多个完整 Stage；同一 build/boundary/secret 事实重复验证，审计脚本假阴性又触发额外恢复。
- **纠偏**：连续批量实现，完整测试/Gate、CURRENT/History/learning、Review、commit 默认后移到 Stage 末。
- **防回归**：衡量执行效率时区分“有效工程产出”和“治理往返”；可靠性要求不等于高频重复验证。

## CW-S3-001｜一体化 smoke harness 把进程编排问题伪装成应用启动失败

- **现象**：同时 spawn fixture/API/client 的脚本报告 `API did not start`，stdout/stderr 为空。
- **恢复**：先检查 `dist/main.js`、AppModule load、真实 listener；直接 Nest 启动 `/health=200`。
- **根因**：smoke harness 的 child readiness/进程编排，不是 ChatWeb bootstrap。
- **纠偏**：fixture、API、client 拆为独立进程，真实 HTTP/SSE 全 PASS；不重复跑已通过的代码测试。

## CW-S4-001｜把 dev/HMR 噪音误当 production UI 失败

- **现象**：真实 Chrome 打开 `next dev` 时 HMR WebSocket 持续报错。
- **根因**：把开发服务器 HMR execution harness 与 Sites/static production artifact 混在一起验收。
- **纠偏**：最终 Browser Acceptance 切到真实 `next build → out/ → serve`；production Console 0/0。

## CW-S4-002｜自动化等待与 fixture timing 伪装成 Stop 失败

- **现象**：Playwright stable-click 超时、slow fixture 在工具往返期间自行完成，曾错过 Stop 窗口。
- **根因**：automation timing/harness 行为，不是 Stop/Abort 实现缺失。
- **纠偏**：用 snapshot/DOM/network 恢复页面事实并控制 fixture timing；最终 Stop→Retry PASS。

## CW-S5-001｜immutable stale snapshot 覆盖 Context failure facts

- **现象**：required ContextProvider 失败时 repository 中 `contextResolutions` 被旧 run snapshot 覆盖。
- **根因**：terminal catch 仍持有旧 immutable aggregate。
- **纠偏**：terminal transition 前回读 persisted run，再基于最新 authoritative snapshot 写终态。

## CW-S5-002｜测试绿但 Context order 已漂移

- **现象**：实现和测试一度使用 registry registration order，而冻结语义要求 request selection order。
- **纠偏**：registry 只做 allowlist/budget lookup，不重排 selection；用反序 fixture 防回归。

## CW-S5-003｜缺公开 env 的 Web build RED 不是 S5 回归

- **现象**：Next build 因缺 `NEXT_PUBLIC_CHATWEB_API_BASE_URL` fail-fast。
- **纠偏**：不削弱校验，补齐公开本地 API URL 后 build PASS。

## CW-S5-004｜Consumer 复制了 Provider capability ceiling

- **现象**：ChatWeb 曾复制 ProFlow RAG 当前 capability ceiling。
- **纠偏**：consumer 只拥有 request budget；provider 拥有 capability policy ceiling。

## CW-S6-001｜实现已进 S6，但活跃文档仍停在旧阶段

- **现象**：Citation candidate 已存在时，README/SDD/CURRENT/旧 handoff 仍停在 S5/P4。
- **纠偏**：做 Spec ↔ CURRENT ↔ README ↔ code ↔ contract 一致性审计，历史材料移入历史区。

## CW-S6-002｜坏 Citation 被拒绝，但 Browser 卡在“正在思考”

- **现象**：非法 Citation fail-closed 后 UI active state 未终止。
- **纠偏**：post-start protocol violation 时 best-effort cancel + Assistant FAILED + active state cleanup。

## CW-S6-003｜S0 的 Artifact 词汇与 S6 真实范围冲突

- **现象**：早期 V0 wording 把 Artifact 当成当前对象，但真实 producer 只有 text + Citation。
- **纠偏**：S6 Product/Domain Amendment，Artifact 延后到真实 producer。

## CW-S7-001｜Context discovery outage 被错误当成权威空 allowlist

- **现象**：503/非法 metadata 后 preference 被当成空列表持久化，导致 Context 选择永久丢失。
- **纠偏**：只有成功 discovery 才能 reconcile/清理；失败时保留 safe last-known preference。

## CW-S7-002｜保护 Context preference 时误伤 Model preference 持久化

- **现象**：第一层修复简单禁止 outage 时写 preference，导致 Model 切换也无法保存。
- **纠偏**：Model 与 Context persistence ownership 分离。

## CW-S8-001｜把 Provider discovery 错当成 Runtime execution enablement

- **现象**：第一版 Registry 自动注册 Provider 自报 Tool。
- **纠偏**：`register(provider, allowedTools)`，discovery/enablement/approval 分层。

## CW-S8-002｜Tool allowlist descriptor 浅冻结导致嵌套 schema 可漂移

- **现象**：nested JSON Schema 仍与 caller 共享引用。
- **纠偏**：注册时 JSON-compatible deep clone + deep freeze。

## CW-S9-001｜Dev Tunnel create 的 rate-limit 表象其实是资源配额

- **现象**：persistent tunnel create 返回 rate-limit。
- **根因**：账号资源数量配额，而不是产品网络故障。
- **纠偏**：先枚举 ownership，只清理可证明无使用的孤儿资源。

## CW-S9-002｜finish-only access log 会漏掉 SSE client disconnect

- **现象**：stream 中断可能只触发 `close`。
- **纠偏**：`finish/close` 双终态 + exactly-once guard。

## CW-S9-003｜过快 fixture 把 close-path 验收变成 completed

- **现象**：客户端“断开”前 fixture 已自然结束。
- **纠偏**：换慢 fixture 控制时序，不修改正确产品语义。

## CW-S10-001｜Traceability 只做正向检查会让验收表变成需求真源

- **纠偏**：同时做 Owner Spec→Matrix 与 Matrix→Owner Spec。

## CW-S10-002｜Verification 已要求 Model timeout，但 Runtime 没有 deadline

- **纠偏**：新增 Runtime-owned `MODEL_PROVIDER_TIMEOUT_MS`，并与 caller cancel 分离。

## CW-S10-003｜Model timeout 默认值出现双真源

- **纠偏**：Runtime config 是 timeout policy 唯一 owner；adapter 只执行显式 deadline。

## CW-V0-001｜fresh verify 终态因工具连接中断丢失

- **现象**：fresh clone verify 过程 PASS，但原 PID 终态无法回收。
- **纠偏**：保留同一 clone/setup，只重跑幂等 verify，直到明确 `V0_FRESH_VERIFY_EXIT=0`。

## S11｜Web Search / One-hop Tool Loop

- **CW-S11-001｜4B grounding/title drift**：Search source 原文被小模型扩成 CEO/CMO/翻译；纠偏为 exact-text grounding + tail guard。
- **CW-S11-002｜Source Gate 误把类型 metadata 当 execution**：Gate 改为审 execution source，不删除正确 Domain metadata。
- **CW-S11-003｜Next dev listener 卡死不是产品失败**：局部 dev runtime stale，只恢复对应 harness。

## S12｜Chat 产品化与多模态

- **CW-S12-001｜旧 Runtime 漂移伪装成新 UI contract 失败**：4300 已加载新 Web，4310 仍是旧 dist；先恢复 listener/build 权威状态，未修改正确 Browser contract。
- **CW-S12-002｜file input/actionability timeout 不是上传功能失败**：早期 Wave C 自动化失败先按 harness 分域处理，最终真实 multipart/preview/delete/send/bind 通过。
- **CW-S12-003｜手机端口活着不等于模型服务可用**：TCP OPEN 但 HTTP timeout；ChatWeb 正确 `PROVIDER_TIMEOUT`，恢复后再补真机证据。
- **CW-S12-004｜PDF/DOCX 首次拒答不等于 parser 失败**：production-dist + direct replay + transparent proxy 均证明 payload 正确；最终裁决为单次小模型/运行态偶发。
- **CW-S12-005｜MCP READY 不等于 MCP execution endpoint**：F1 `/readyz` 只能证明 manager runtime；F2 必须有真实 shared execution seam，不能把 health/operator URL 改写成 `/mcp`。
- **CW-S12-006｜单一 shared owner 不等于所有 Tool 都能执行**：Playwright 有 broker execution endpoint；Local Dev 没有，因此 Local Dev READ_ONLY 仍必须 `UNAVAILABLE` fail-closed，不能为了 UI 对称启动第二个 Desktop Commander。
- **CW-S12-007｜内部 provenance 直接序列化会穿透 public wire**：真实 Search 暴露 `Citation.providerId`；修正为 explicit internal→public projection，而不是删除内部 provenance。
- **CW-S12-008｜黑色 `N` 不是个人中心**：截图看起来像头像入口，但真实语义是 Next.js Dev Tools indicator；源码没有 Profile/Account/User Menu。关闭 dev indicator，不为误判去删除产品设置。
- **CW-S12-009｜附件入口不是“技术上能上传”就够了**：用户明确只要 Paste + Drag&Drop；最终删除 hidden file input/file picker/“＋附件”，底层 upload/store ownership 不变。
- **CW-S12-010｜Playwright `Meta+V` 失败不能判 Paste 产品坏了**：最小纯文本 system-clipboard probe 同样无法进入 textarea，机械证明当前缺口在 Playwright/Extension clipboard bridge；保持 `HARNESS_FAILURE / NOT_APPLIED`，不注入 synthetic ClipboardEvent 冒充 PASS。
- **CW-S12-011｜一个 Playwright MCP 进程仍可能共享 current-page state**：raw owner 已统一后，多 Chat 仍会因 stateful page/context 共享发生漂移。纠偏为 owner uniqueness 与 session isolation 分层；公共 Acceptance Skill 固化 atomic target-bound scene，不在 ChatWeb 内造第二套 SOP。
- **CW-S12-012｜长生成不能塞进单次 Browser 工具预算**：Search/Think 一次调用超过工具时限时，先按 owner 做 side-effect reconciliation，再把场景拆成“提交”和“按唯一 scene identity 回收终态”两段，避免重复发送。
- **CW-S12-013｜参数卡写了对称 padding 但视觉仍不对称**：隐藏说明虽然 `display:none`，原两行 Grid 仍保留 ghost track/`row-gap`；前几轮只调 padding 没有触达真实 owner，最终用 DOM geometry + computed grid tracks 定位。详情见 `15_S12_Settings_UI精修与吞吐复盘.md`。
- **CW-S12-014｜手写 Hover 持续产生位置与 pointer-gap 补丁**：React hover state + absolute/fixed magic offset 导致 anchor 漂移、鼠标移入内容提前消失；后续应统一成熟 HoverCard/Tooltip primitive，不再按位置叠加偏移。详情见 `15_S12_Settings_UI精修与吞吐复盘.md`。

S12 最终状态：Wave A/B/C/E/F/D 全部 Final PASS，`S12_FINAL_PRODUCT_GATE=FINAL_PASS / S12_CHAT_PRODUCTIZATION=FINAL_ACCEPTED`；下一门是 `V0_SITES_PRODUCTION_GATE`。
