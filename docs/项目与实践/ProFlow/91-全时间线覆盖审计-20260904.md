## 5. 缺口 B｜Custom GPT 从在线配置变成外部 Deployment Resource

现有文档虽然多次提到 provisioning，但缺少独立的 Decision Episode。

历史链已足够完整：

```text
人工 Builder 配置 / ACTION_REQUIRED_WEB
→ Git Role/Profile/Release 资产化
→ Real-2 冻结真实 GPT provisioning
→ 两阶段 create / cross-tab / publish/private visibility 多轮修正
→ reusable createCustomGptRole API
→ Product/Controller/Test-Ops 全部迁移公共 API
→ manual wizard 删除
→ Bearer Auth 前置，single-stage provisioning
→ post-create Gateway/Carrier validation + recovery
```

关键不是“自动填表”，而是：`LIVE_CREATED` 后远端 GPT 已成为不可逆外部 Reality；validation failure 不能把它回滚成 MISSING 后重复创建。`g-id` 是 durable Role resource identity，`c-id` 是 Worker Conversation identity，Tab 只是 locator。

因此它具备独立升级资格：**把第三方 SaaS 里的 Agent 配置物化成可版本化、可部署、可验证、可恢复的外部资源。**
## 6. 缺口 C｜命令结果不能冒充现实：UNCERTAIN → UNKNOWN → Reconciliation

这条语义有明确历史前身，而不是 Phase 3 纸面设计。

`GIT_VERIFIED`：Phase 2 从 08-04 设计期就存在 `UNCERTAIN`；08-06 `c3ea9bf` / `1a7244a` 强化 uncertain reporting 与 durable recovery，08-07 `f45e7ce` 处理 Browser lifecycle / exactly-once recovery，真实 Level-3 最终又出现 `UNCERTAIN / USER_CONTROL_ACTIVE`。

08-11 `47d5871` 正式冻结 `Result / Evidence / UNKNOWN_SIDE_EFFECT / Recovery`：Effect 开始后结果失联，不能直接 FAILED+retry，而要先读取现实 postcondition；仍无法判定则保持 UNKNOWN/STOP/Human。

当前 ProFlow 把它落实成 `APPLIED / NOT_APPLIED / UNKNOWN`：Local Execution、Browser Effect、Agent Delivery 各自在 Owner 内 reconciliation；Task 不把技术 UNKNOWN 自动翻译成 workflow WAITING/FAILED。Release 又把相同原则扩到 npm Registry：publish 命令 timeout/non-zero 后先 exact readback，Registry 已存在则接受 APPLIED reality，仍不明确则禁止 blind republish。

核心判断：**命令的 transport/exit status 不是现实副作用的最终真值；不能证明没发生，就没有资格安全重试。**
