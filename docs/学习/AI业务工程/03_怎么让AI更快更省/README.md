# 03 怎么让 AI 更快更省

AI 已经能把事情做好以后，才值得谈优化。这里的“更快更省”不是单纯压模型价格，也不是看到 Token 多就删 Prompt，而是把一条任务从进入系统到得到可用结果的等待、Token、调用、工具和返工一起看。

这个目录只保留两篇正文，职责明确分开：

1. [01_AI为什么会越来越慢越来越贵.md](01_AI为什么会越来越慢越来越贵.md) —— 先做诊断。回答一条 AI / Agent 任务的钱和时间到底花在哪里，Token 为什么会膨胀，长任务为什么越跑越重，以及 Cache、Batch、并行、本地模型分别解决什么。核心是先判断瓶颈究竟属于 Token 数、Token 单价、调用次数、工具等待还是返工。
2. [02_怎么节省Token.md](02_怎么节省Token.md) —— 专门讲 Token Engineering。按工程手段归类，而不是按项目罗列：先把确定性步骤程序化、CLI/脚本化，再做结构索引与按需取数、Tool 边界治理、Context/Prompt/表示压缩、History/State/Memory 生命周期、Cache 与复用、输出预算和模型分工；CodeGraph、RTK、Headroom、Repomix、Serena、Caveman 等都作为各类手段的真实实现来理解。

阅读顺序：**先用第 01 篇找到“慢和贵”的来源；确认问题落在模型调用与 Context 后，再用第 02 篇决定具体怎么减。**
