# A2A 解决了什么问题

> 唯一职责：解释同一运行系统内部怎样直接协调、跨独立运行边界怎样通信，以及什么时候才需要 A2A。
> 前置阅读：多主体组织、长期任务运行、信息状态与安全恢复章节。

<a id="ch14-learning-question"></a>
## 从一个跨组织协作请求开始

一家公司里的研究 Agent 要把一段代码修改任务交给另一个团队维护的 Coding Agent。对端有自己的身份、权限、Runtime 和任务生命周期；调用方既不应该读取它全部 Memory，也无法直接操纵它内部 Tool。这里需要的已经不是“调用一个函数”，而是两个独立责任主体之间的协作边界。

### 本节新词

- **A2A / Agent2Agent Protocol（智能体到智能体协议）**：让彼此独立、内部实现可以不透明的 Agent 发现能力、交换消息、管理协作任务并交付结果的互操作协议。
- **Responsibility Boundary（责任边界）**：调用方只约定对端要承担什么工作、输入输出和状态，不要求掌握对端内部 Model、Memory、Tool 或 Workflow。

沿用 Subagent 章已经学过的 Independent Agent：当另一端拥有自己的身份、责任、生命周期和权限时，把它压成 Tool/Capability 会丢掉协作语义。跨 Runtime 的两个独立 Agent 需要在不暴露内部 Memory/Tools 的情况下发现彼此、跟踪任务并交付 Artifact（产物），A2A 正是为这段边界服务。

## 从互操作协议走到本地责任映射

<a id="ch14-a2a-boundary"></a>
### 3.1 先判断 Capability 还是 Independent Responsibility Subject（独立责任主体）

Tool/MCP 章已经定义 Capability，Subagent 章已经定义 Independent Agent。这里把两条边界放到同一个判断里：远端系统即使内部有 LLM、数据库和长任务 API，对调用方仍可能只是一个 Operation provider；只有它对一段 Goal、State、Lifecycle 和结果责任独立负责时，A2A 的协作语义才成立。

一个实用判断是：

```text
Operation contract → Tool / MCP 倾向
Goal + independent planning/state/lifecycle/responsibility → Independent Agent / A2A 倾向
```

这是工程判断，不是协议规范的绝对二分。

<a id="ch14-agent-card"></a>
### 3.2 Agent Card（智能体名片）：对外自描述，不是完整内部组织图

#### 本节新词

- **Agent Card（智能体名片）**：A2A 用于描述远端 Agent 身份、接口、能力和安全元数据的自描述对象，供 Discovery 和 Routing 使用。
- **Endpoint（服务入口）**：客户端实际连接远端 Agent 的网络地址。A2A 1.0 的 Agent Card 可通过 `supportedInterfaces` 描述多个协议接口。
- **Security Metadata（安全元数据）**：描述身份认证、授权或安全能力所需的信息；它是声明，不等于本次任务已经获得授权。

Agent Card 用于表达 endpoint/capabilities/skills/security 等 interoperability metadata。它不应泄露 credentials，也不需要把内部 Model、Memory、Subagents 和 Tool topology 暴露出去。

<a id="ch14-message"></a>
### 3.3 Message（消息）：沟通，不等于状态提交

#### 本节新词

- **Message（消息）**：Agent 之间的一次通信内容。自然语言“我完成了”属于 Message，不自动等于 Task 已进入成功状态。
- **Part（消息部分）**：A2A 1.0 中 Message / Artifact 承载文本、二进制、URL 或结构化数据的内容单元。
- **Soft Communication（软通信）**：可以表达建议、解释和协商，但不能替代受治理 State Commit 的自然语言通信。

Message 表达双方说了什么。自然语言“好了”不能代替 Task status / Artifact / Evidence。Message 属于 soft communication。

<a id="ch14-task"></a>
### 3.4 A2A Task（A2A 任务）：协议协作工作单元，不等于 Runtime Task

#### 本节新词

- **A2A Task（A2A 任务）**：A2A 协议边界内用于跟踪一段协作工作的有状态对象。
- **Runtime Task（运行时任务）**：本地平台内部对 Goal、Policy、Truth 和 Recovery 负责的长期责任对象；它可以映射一个或多个 A2A Task。
- **Context ID（上下文标识）**：A2A 用来关联同一协作上下文中多个对象/交互的身份之一，不应直接替代本地 Runtime Task ID。

正式边界仍然是：`Runtime Task ≠ MCP Task ≠ A2A Task`。

A2A Task 表达远端协作在协议边界上的有状态工作单元。Local Runtime 可以把它映射到本地 Runtime Task，但两个命名空间不能合并；一个本地 Task 也可能协调多个远端 A2A Task。

<a id="ch14-artifact"></a>
### 3.5 Artifact（产物）：协议输出，不自动是 Evidence / Truth

#### 本节新词

- **Artifact（产物）**：A2A Task 对外交付的协议结果对象，可以包含一个或多个 Part。

Durable Execution 已经定义 Evidence 与 Truth Commit。A2A Artifact 只是远端 Task 的协议输出：收到 Artifact 后，本地系统仍可能需要校验版本、内容和成功标准，才能把结果写入本地 Truth。

<a id="ch14-opaque-execution"></a>
### 3.6 Opaque Execution（不透明执行）：互操作不要求共享脑子

#### 本节新词

- **Opaque Execution（不透明执行）**：调用方只依赖对端协议合同，不要求访问对端内部 Model、Memory、Tool、Subagent 或 Workflow。
- **Implementation Independence（实现独立性）**：双方可以使用不同框架、语言和供应商，只要协议边界兼容。

A2A 的价值之一是只约定边界，不要求了解远端使用哪个 Model、Tool、Memory、Subagent 或内部 Workflow。跨组织协作也因此能保护隐私与实现独立性。

<a id="ch14-native-vs-a2a"></a>
### 3.7 Native Coordination（原生协调）vs A2A

#### 本节新词

- **Native Coordination（原生协调）**：同一 Runtime 内直接使用已有 Task Store、Event、Scheduler、State 和 Permission 原语协调 Agent。
- **Cross-Runtime Boundary（跨 Runtime 边界）**：协作双方由独立 Runtime 管理，不能直接共享本地内部状态和生命周期；这时标准互操作协议更有价值。

同一个 Runtime 已经共享 Task Store、State、Event、Scheduler、Permission 时，优先使用 Native Coordination（原生协调）。只有跨独立 Runtime、框架、厂商或组织边界时，A2A 的标准化价值才明显上升。

不要为了“架构先进”让同 Runtime Agent 通过 HTTP 绕一圈。

<a id="ch14-async-mapping"></a>
### 3.8 异步远端更新怎样回到本地 Runtime

#### 本节新词

- **Protocol Adapter（协议适配器）**：把远端协议事件、状态和 Artifact 转换成本地 Runtime 能理解的内部 Task/Event/Artifact 合同。
- **Streaming（流式更新）**：远端在任务进行中持续发送状态或 Artifact 增量，而不是只在结束时返回一次结果。
- **Push Notification（推送通知）**：远端在状态变化时主动通知调用方的异步机制，调用方不需要持续轮询。

```text
Remote Task status changes
↓
A2A update / stream / notification
↓
Local protocol adapter
↓
map to local Task / State
↓
Event / Scheduler
↓
State/Context/Memory 章 Context Assembly
↓
resume model if decision is needed
```

协议负责跨边界送变化；local Runtime 仍负责 Truth、Permission、Scheduler、Recovery。

<a id="ch14-platform-adapter-case"></a>
### 3.8A Case Lens｜Adapter 与 A2A 不在同一层

真实平台可能同时接 OpenCode、Claude Agent SDK、Codex 等不同 Harness。它们各自有 Session、Thread、Turn、Hook 或事件模型，平台通常需要 Adapter 把这些私有 lifecycle 归一成本地 `Task / Event / Artifact / Approval` 合同。

```text
vendor / harness lifecycle
→ Adapter
→ local Runtime contract

independent remote Agent boundary
→ A2A
→ local protocol adapter
→ local Runtime contract
```

这两件事不要混：**Adapter 吸收某个 Harness 的私有表面；A2A 标准化独立 Agent 之间的互操作边界。** 同一个 Runtime 内已有原生 lifecycle/event surface 时，优先直接使用，不需要为了“标准化”绕一层 A2A。

截至 2026-09-03，OpenCode、Claude Agent SDK 与 Codex App Server 都有各自的 session/thread/event 生命周期接口；这些只作为“私有表面确实不同”的当前例子，不在 A2A 章继续展开各厂商事件模型。来源：[OpenCode Plugins](https://opencode.ai/docs/plugins/)、[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/python)、[Codex App Server](https://developers.openai.com/codex/app-server)。

<a id="ch14-mcp-vs-a2a"></a>
### 3.9 MCP 与 A2A 是互补边界

MCP 章已经解释能力连接，这里只比较责任边界：MCP 让一个 Host/Agent 接入 Tool、Resource 等 Capability；A2A 让两个独立责任主体交换协作任务与结果。一个 A2A remote agent 内部完全可以继续通过 MCP 使用 Browser/DB/Git capability。

<a id="ch14-current-facts"></a>
## 当前协议事实｜2026-09-03 · A2A 1.0.0

以下事实于 2026-09-03 按 A2A 官方文档核验：

- 当时最新发布的规范版本是 `1.0.0`；
- 协议面向彼此独立、内部实现可以不透明的 Agent 系统，解决通信与互操作问题；
- 核心数据模型包含 Task、Message/Parts 与 Artifact，Task 可携带状态、产物和可选历史；
- 标准化的 Agent Card 用于描述能力、协议接口和安全元数据；当前官方文档支持通过 `/.well-known/agent-card.json` 发现 Agent Card；
- A2A 1.0 的协议协商使用 `1.0` major.minor 兼容标识，规范网站当前 release 标记为 `1.0.0`。

以上是当前协议事实。以后即使字段名或传输细节变化，A2A 仍然解决同一个问题：让彼此独立的 Agent 互操作。

官方来源：[A2A 最新文档](https://a2a-protocol.org/latest/)、[A2A 当前规范](https://a2a-protocol.org/dev/specification/)、[A2A 1.0.0 文档](https://a2a-protocol.org/v1.0.0/)、[A2A v1.0 发布说明](https://a2a-protocol.org/dev/blog/2026/03/12/a2a-protocol-ships-v10-production-ready-standard-for-agent-to-agent-communication/)。

本章已把稳定协议概念与当前规范版本分开。

## Protocol Task 与 Local Task 为什么必须保留双层状态

跨 Runtime 时最好显式保留两个世界：

```text
A2A Task
= protocol-visible remote collaboration state

Local Runtime Task
= local responsibility / policy / truth / recovery state
```

Adapter 负责 mapping，但不应把远端 Agent 的一句 status update 直接写成 local Truth；仍要按本地 policy/evidence/ownership 处理。
