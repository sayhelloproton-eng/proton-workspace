# ChatWeb｜历史证据与决策档案

本文保存 ChatWeb 从 2026-09-06 起的阶段基线、关键 commit、真实故障、机械证据和被 supersede 的路线。它不是当前 Spec；当前产品已经继续演进，尤其 Tool/MCP 与 Intelligent Search 边界发生过后续修订，任何当前状态都必须回到 `repos/chatweb` 的 CURRENT、Owner Spec、源码和真实 Runtime。

## 1. S0｜先拆产品，再写 UI

S0 最初 0 业务代码，目标是冻结产品边界、Provider 分类、Conversation/ChatRun、Streaming/Retry、Context composition、Public Web 和阶段路线。

第一版 Gate 只统计 11 个 PRD Requirement，显示 11/11 PASS；全量审计才发现一共 33 个 Requirement，其中 22 个非 PRD Requirement 没进入 Acceptance Matrix。纠偏后改成全仓 Requirement ID → Acceptance mapping → Verification definition，最终 S0 34 Requirement 全闭环。

另外明确：`ModelProvider.listModels()` 不是所有 OpenAI-compatible endpoint 的强制能力；可以由 server allowlist 提供 metadata。Retry 只面向未成功 run；completed answer Regenerate 延后到真正 branch/answer-selection 需求。

当时 ChatWeb Git 一度处于 UNBORN HEAD、0 commit；学习记录不允许把未来 S5/S8 的设计提前写成已实现事实。

## 4. S5｜Context / RAG 真正成为插件能力

Generic Context Runtime implementation=`b9ab9d9`；ProFlow RAG adapter=`e1f034c`；consumer/provider policy decoupling=`fea5b4f`。

Targeted suite 从 16/17 RED 到 17/17，再加入 selection/budget guard 后 18/18；concrete adapter 后最终 22/22。

两个重要真实 bug：

1. required Context failure fact 已写 repository，但 catch 用旧 immutable run snapshot 写 FAILED 时把它覆盖；修复为 terminal transition 前回读 authoritative run。
2. 实现和测试一度一起漂成 registry registration order；最终 fixture 故意让 registry=`first→second`、request=`second→first`，证明 frozen selection order 才是语义。

真实 cross-repo E2E 覆盖 zero-RAG、required success、optional unavailable、required fail-closed；Knowledge DB read-only。

## 5. S6｜Citation 与 public stream 安全

S6 implementation=`f7f8ae6`，context baseline=`d60b262`；最终 API 24/24 + Web stream contract 6/6 = 30/30。

核心演进：新增 `message.citations` public event；Citation 绑定 run/message；unsafe href fail closed；HTML/script/img 只作文本。

真实 Browser 曾出现“非法 Citation 被 parser 拒绝，但 UI 仍停在正在思考”。最终 post-start protocol violation 变成 best-effort cancel + Assistant FAILED + active state cleanup。Final Review 后又增加 runId/assistantMessageId stream ownership，拒绝 duplicate start/citation、citation-after-delta、post-terminal event、EOF 缺 terminal。

同期还做了 SDD 清理：早期 Artifact 被写成 V0 当前对象，但没有真实 producer，最终从当前 Ubiquitous Language 移除，等真实 producer 再单独 Amendment。

## 6. S7｜Settings 是 capability selection，不是 secret admin

Implementation=`62e862d82141f0ae43cfd1b6cb823604daedfdef`，context=`203fb4e`；API 26/26 + Web 11/11 = 37/37。

Discovery outage 的两层 bug：第一次把 503/非法 metadata 当权威空 allowlist，擦掉 Context preference；第一刀禁止 outage 时全部 persistence，又让 Model selection 无法保存。最终 Model 与 Context preference ownership 分离，last-known Context 只保留安全 `providerId/failurePolicy`，private field 被清洗。

Retry body 为空，不读取当前 Settings；旧 run 的 frozen selection 继续有效。

## 11. S12｜产品化、多模态、Tool UX、MCP、Voice

### Wave A/B

UI 从工程验证壳收敛成 Chat 产品。Browser 不再暴露 raw model；只表达 `thinkingMode=off|on`。真实手机 Runtime 证明 `chat_template_kwargs.enable_thinking` 有效，Think 用 hidden reasoning pass → clean final pass。

### Wave C Attachment / Vision / Document

Attachment ownership 收到 immutable UserMessage；multipart 上传后 ChatRun 只带 attachmentId。API 60/60、Web 10/10、PDF/DOCX provider tests 3/3。真实 Vision+Markdown 曾返回 `WAVE C / VISION 42` 与 `ORANGE-NEBULA-731`；PDF/DOCX 最终回读 `VIOLET-COMET-842 / TEAL-ORBIT-519`。

首次 PDF/DOCX 真机拒答通过 production-dist message、direct phone replay、transparent outbound proxy 证明 payload 完整，裁决为单次模型/运行态偶发，没有误改 parser。

### Wave E public Tool UX

源码新而 4310 `/chat/tools` 仍 404，最终证明 listener 仍加载旧 pre-change dist。只替换 4310 并恢复精确 server-only env 后通过。

随后真实 Search 又暴露 internal `Citation.providerId="web"` 进入 public SSE；修成 explicit internal→public projection，保留内部 provenance，不让 Browser 看到 private owner identity。

### Wave F MCP

F1 发现已有 canonical shared MCP owner，禁止 ChatWeb direct-spawn 第二个 Desktop Commander/Playwright controller。F2 进一步区分 readiness 与 execution endpoint：Playwright 有 broker seam，Local Dev 无 shared execution seam，所以后者必须 UNAVAILABLE。

F2 历史证据：API 78/78 + Web 10/10、endpoint-authority 12/12；Chrome 5 个 READ_ONLY AVAILABLE，MUTATING `UNAVAILABLE + approvalRequired=true`；真实 `browser_snapshot` one-hop PASS。

### Wave D Voice

主链：Browser SpeechRecognition → `/chat/voice/normalize` → normal ChatRun → Browser speechSynthesis。最终 API 83/83、Web 10/10；两轮真人 speech flow 均 normalize 201 → chat 200，用户确认 TTS 可听。

### Final Product Gate

历史终态曾达到：Fast=`FAST-OK`、Think=`THINK-OK`、Drag&Drop Vision/File=`RED | FILE-CODE-731`、Search run + 5 Citations、Chrome READ_ONLY MCP=`MCP-OK`、Stop cancel=201、同 scene Retry 完成且 duplicate User=0。S12 当时 `FINAL_PRODUCT_GATE=FINAL_PASS`。

这些证据证明当时能力真实存在，但不自动代表今天 live product surface 仍保留全部能力。

## 12. 后续产品边界收缩：Web Chat Only

2026-09-13/14 的当前 Spec 把 live architecture 收敛为 Web Chat：ModelProvider + ContextProvider + Intelligent Web Search；Tool Drawer、generic Tool catalog、Local Dev、Chrome control、MCP discovery/execution、public `toolSelections` 被列为 Retired Surface。

Intelligent Search 改为 bounded multi-round：默认 max rounds=6、硬上限 10、max results 默认 5/上限10；Browser 只暴露 off/auto。旧 S8/S12 Tool/MCP 证据保留为架构学习，不允许反向把历史 PASS 当作当前产品需求。

## 13. UI 精修与自动化经验

设置右栏曾出现“CSS padding 已对称但视觉上下留白仍不对称”。真实 Playwright geometry 发现说明文本虽 `display:none`，Grid 仍保留 ghost track + `row-gap:6px`，真正 owner 是 layout track 而不是 padding 数字。这个案例终止了连续多轮“看截图猜像素”的试错。

Tooltip/Hover 早期使用 React hover state + absolute/fixed magic offset，逐渐出现 anchor 漂移、pointer gap、collision 分叉；结论是应使用成熟 HoverCard/Tooltip primitive，而不是继续叠数值补丁。

共享 Playwright 还暴露：single raw owner 不等于 per-consumer page/context isolation。通用解决方式最终提升到 workspace Acceptance Automation Skill，ChatWeb 不再维护自己的 tab-index workaround。

Paste E2E 也保持证据边界：系统 clipboard 的纯文本 `Meta+V` 都无法进入 textarea，因此附件 Paste 自动化缺口裁决为 Harness failure，没有用 synthetic ClipboardEvent 冒充真人路径。

## 14. 长期保留的工程判断

- 部署环境和 secret location 必须进入架构输入；
- Message 与 ChatRun 分离是 Stop/Retry/partial history 的基础；
- public DTO 不能直接复用内部 Domain object；
- discovery、readiness、enablement、execution、approval 是不同层；
- Runtime/source/Browser/Harness 是不同 failure domain；
- 测试绿不代表 Spec 没漂，Final Review 仍要跨层核对；
- 历史 capability PASS 不等于当前产品必须继续暴露它；
- 技术可重建、正式生产发布、公开源码治理必须分开。
