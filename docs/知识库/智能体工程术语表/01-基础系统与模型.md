# L0-L1｜基础系统与模型

> 这一层回答：**模型是怎么运行的，AI 工程为什么先要懂系统、协议和模型基本机制？**
>
> 阅读方式不是按字母背词，而是先看下面的关系链，再把每个术语放回真实系统位置。

~~~text
系统运行基础 → 网络与协议 → 模型结构 → Token/Attention → 生成与采样 → 训练/后训练 → 推理与部署
~~~

## 术语表

| 术语 | 一句话 | 典型场景 | 关键边界 / 易混 |
|---|---|---|---|
| Runtime（运行时） | 程序真正执行时依赖的环境、资源和运行机制。 | Browser Runtime、Node Runtime、Agent Runtime 都是在回答“代码或模型在哪里、靠什么跑”。 | Runtime ≠ Framework；Framework 组织开发方式，Runtime 负责真正运行。 |
| Process（进程） | 操作系统中正在运行的程序实例，拥有独立地址空间和 PID。 | API 服务、模型服务、Gateway、Browser Broker 启动后都有真实 Process。 | Process ≠ Task；前者是执行载体，后者是业务工作对象。 |
| Thread（线程） | 进程内部的执行单元，可以与同进程其他线程共享内存。 | 模型推理、浏览器、Server Runtime 的并发实现会涉及线程。 | Thread ≠ Process；线程共享进程资源。 |
| Event Loop（事件循环） | 用事件队列推进异步回调和 I/O 的运行机制。 | Node.js、Browser 中大量异步任务都围绕 Event Loop。 | Event Loop ≠ 多线程；它可以在单主线程上组织大量异步 I/O。 |
| Protocol（协议） | 多个参与方交换消息、状态和错误时共同遵守的规则。 | HTTP、JSON-RPC、MCP 都属于协议或协议体系。 | Protocol ≠ API；API 是能力接口，Protocol 是交互规则。 |
| API（应用接口） | 一个系统向另一个系统暴露可调用能力的接口。 | Chat 产品调用模型、RAG、搜索服务。 | API 可以使用 HTTP，但 HTTP 本身不是业务 API。 |
| Schema（结构约束） | 对字段、类型、必填项和合法结构的机器可检查描述。 | Tool 参数、Structured Output、事件、Task Contract。 | Schema ≠ 数据；Schema 定义数据“应该长什么样”。 |
| Serialization（序列化） | 把内存对象转换成可存储或传输格式。 | 对象转 JSON、Protobuf 后通过网络传输。 | Serialization ≠ Protocol；协议可以选择一种序列化格式。 |
| JSON | 常见的文本数据交换格式。 | REST API、Tool 参数、配置和事件。 | JSON 只是格式，不等于 JSON-RPC 或 API。 |
| HTTP | Web 最常见的请求/响应通信协议。 | Browser 调 API、服务间 REST 通信。 | HTTP ≠ REST；REST 是一种 API 设计风格。 |
| Request（请求） | 调用方发送给服务端的一次输入消息。 | HTTP 请求、RPC 调用、模型 API 调用。 | Request ≠ Task；一次 Task 可以发出很多 Request。 |
| Response（响应） | 服务端针对 Request 返回的结果或错误。 | API 返回 JSON、流、状态码。 | 收到 Response 只说明通信有结果，不一定等于业务 Effect 已确认。 |
| URL | 定位 Web 资源或接口地址的标识。 | 调用模型端点、RAG API、站点页面。 | URL 包含资源位置语义，不等于网络连接本身。 |
| DNS | 把域名解析成网络地址的系统。 | 站点、API 域名连接前的名字解析。 | DNS 失败与应用 API 失败属于不同层。 |
| TCP | 提供可靠字节流传输的网络协议。 | HTTP/1.1、HTTP/2 等常建立在 TCP 之上。 | TCP 保证传输语义，不保证业务事务成功。 |
| TLS | 为网络连接提供加密、身份校验和完整性保护的协议。 | HTTPS、远程模型 API、企业服务通信。 | TLS 解决通信安全，不替代应用 Authorization。 |
| RPC | 把远端能力抽象成类似函数调用的通信模型。 | 服务间调用、JSON-RPC、gRPC。 | RPC 是交互模型，不等于某一种具体传输。 |
| JSON-RPC | 用 JSON 表达远程方法调用、响应和错误的一套协议。 | MCP 数据层的重要基础。 | JSON-RPC ≠ JSON；前者定义调用语义。 |
| SSE | 基于 HTTP 的服务端持续事件流。 | AI Chat 流式输出 token、进度事件。 | SSE 主要是 Server → Client 单向推送。 |
| WebSocket | 建立长期双向消息通道的协议。 | 双方都需要持续主动发消息的实时交互。 | WebSocket ≠ SSE；后者更适合服务端单向持续推送。 |
| Sync（同步） | 调用方等待当前操作完成后再继续。 | 简单函数、短 API 调用。 | Sync ≠ Blocking 完全等价；实现细节还取决于 Runtime。 |
| Async（异步） | 发起工作后可以先释放当前控制流，稍后再接收结果。 | 远程 Job、Tool、模型流式执行。 | Async ≠ Parallel；异步强调等待方式。 |
| Concurrency（并发） | 同一时间段推进多个任务的能力。 | 多个请求、多个 Agent Task 同时存在。 | Concurrency ≠ Parallelism；并发不要求同一时刻物理并行。 |
| Parallelism（并行） | 多个计算在同一时刻真正同时执行。 | 多核、GPU、多 Worker。 | Parallelism 是执行形态；Concurrency 是任务组织能力。 |
| Backpressure（背压） | 下游处理不过来时，主动限制上游继续灌入工作。 | Streaming、Queue、批量 Tool 调用。 | Backpressure ≠ Retry；它是在过载前调节流量。 |
| Timeout（超时） | 在规定时间内没有得到确定结果。 | Tool/API/Build 等待超过期限。 | Timeout ≠ FAILED；有 Side Effect 时业务结果可能是 UNKNOWN。 |
| Cancellation（取消） | 请求系统停止仍在进行的工作。 | 用户 Stop、Task 取消、长模型调用终止。 | Cancellation ≠ Rollback；已经发生的副作用不会自动撤销。 |
| LLM（大语言模型） | 根据上下文预测并生成语言或结构化输出的模型。 | Chat、代码生成、规划、工具选择。 | LLM ≠ Agent；Agent 还需要 Runtime、State、Tool。 |
| Foundation Model（基础模型） | 通过大规模训练形成通用能力、可被下游适配的模型。 | GPT/Qwen 等通用模型家族。 | Foundation Model ≠ 特定 Agent 应用。 |
| Base Model（基座模型） | 主要完成预训练、尚未充分对齐指令交互的模型版本。 | 继续做 SFT、后训练或专项适配。 | Base Model ≠ Instruct Model。 |
| Instruct Model（指令模型） | 经过指令数据和后训练，能够稳定遵循用户任务的模型。 | Chat、Agent Runtime 常使用。 | Instruct ≠ Base；它是后训练后的交互形态。 |
| Chat Model（对话模型） | 以多角色消息结构接收输入并生成回复的模型接口形态。 | System/User/Assistant 消息。 | Chat Model ≠ Agent；对话格式不提供长期任务状态。 |
| Transformer | 以 Attention 为核心的序列建模架构。 | 现代 LLM、多模态模型底座。 | Transformer ≠ LLM；它是模型架构。 |
| Token | 模型处理文本时使用的离散符号单位。 | Context Window、计费、吞吐、输出长度。 | Token ≠ 字符或单词。 |
| Tokenizer | 把文本编码为 Token、再把 Token 解码回文本的组件。 | 模型请求进入推理前。 | Tokenizer 与模型 Vocabulary 必须匹配。 |
| Tokenization | 文本被切分、编码成 Token 序列的过程。 | 估算 Context 长度、理解中英文 token 差异。 | Tokenization 是过程；Tokenizer 是执行组件。 |
| Vocabulary | Tokenizer 可表示的 Token 集合。 | 模型输入输出编码。 | Vocabulary 大小不等于模型能力。 |
| Embedding Matrix | 把 Token ID 映射成连续向量表示的参数矩阵。 | Transformer 输入层。 | Embedding Matrix ≠ RAG Embedding Model。 |
| Self-Attention（自注意力） | 让序列中每个位置根据相关性读取其他位置的信息。 | Transformer 建立长距离上下文关系。 | Self-Attention ≠ 外部 Memory。 |
| Query / Key / Value | Attention 中用于计算“读谁、读多少、读到什么”的三类向量。 | 理解 Attention 机制。 | 这里的 Query 不是搜索系统里的用户查询。 |
| Multi-Head Attention | 并行使用多组 Attention 子空间捕捉不同关系。 | Transformer 层。 | 多个 Head 不是多个 Agent。 |
| RoPE | 通过旋转位置编码把相对位置信息注入 Attention。 | 现代 LLM 的位置建模。 | RoPE ≠ Context Window 本身。 |
| FFN | Transformer 层中对每个位置独立进行非线性变换的前馈网络。 | Attention 后的特征变换。 | FFN 与 Attention 承担不同计算。 |
| Residual Connection | 把子层输入直接加到输出，帮助深层网络稳定训练。 | Transformer Block。 | Residual ≠ Memory。 |
| LayerNorm | 对隐藏表示做归一化以稳定训练和推理。 | Transformer 层。 | LayerNorm 是数值稳定机制。 |
| Context Window | 一次模型调用允许处理的最大 Token 范围。 | 长对话、长代码、RAG Context。 | Context Window 是容量；Runtime Context 是实际装进去的工作集。 |
| Autoregressive Generation | 按前面已有 Token 逐步预测下一个 Token 的生成方式。 | LLM 文本生成。 | 一次只生成下一步，不等于没有并行计算。 |
| Next-Token Prediction | 根据已有上下文预测下一个 Token 概率分布的训练/生成目标。 | 理解语言模型基本目标。 | 会预测下一个 Token 不等于只会局部模式匹配。 |
| Causal Mask | 限制生成模型不能在当前位置读取未来 Token。 | Decoder-only 模型。 | Causal Mask 与权限控制无关。 |
| Logits | 模型在 Softmax 前对各 Token 给出的未归一化分数。 | 采样阶段。 | Logits 不是概率。 |
| Softmax | 把一组分数归一化成概率分布。 | Token 采样。 | Softmax 之后还可能受 Temperature/Top-P 等影响。 |
| Sampling（采样） | 根据模型概率分布选择下一个 Token 的过程。 | 生成多样性控制。 | Sampling ≠ Reasoning。 |
| Temperature | 缩放概率分布尖锐程度的采样参数。 | 控制随机性。 | Temperature 低不等于事实一定正确。 |
| Top-K | 只保留概率最高的 K 个候选进行采样。 | 文本生成参数。 | Top-K ≠ Retrieval Top-K；名字相同但层级不同。 |
| Top-P | 保留累计概率达到阈值的一组候选再采样。 | 生成多样性。 | Top-P 是 nucleus sampling 参数。 |
| KV Cache | 缓存历史 Token 的 Key/Value，减少自回归解码重复计算。 | 长生成、模型服务性能。 | KV Cache ≠ 应用层 Cache。 |
| Prefill | 一次性处理输入 Prompt、建立初始 KV Cache 的阶段。 | 推理延迟分析。 | Prefill 计算特征与后续逐 Token Decoding 不同。 |
| Decoding | 模型在 Prefill 后逐步生成新 Token 的阶段。 | Streaming 输出。 | Decoding 性能常决定长输出速度。 |
| Prompt | 当前调用直接给模型的指令、问题或示例表达。 | System/User 指令、Few-shot。 | Prompt ≠ 完整 Context。 |
| System Prompt / System Instruction | 由高优先级运行层提供的长期或本轮系统指令。 | 定义角色、规则、输出约束。 | 不能让低权网页内容覆盖 System Instruction。 |
| User Message | 用户在当前对话轮次提供的任务或信息。 | Chat 输入。 | User Message 不自动拥有越过系统安全边界的权限。 |
| Assistant Message | 模型作为助手在对话中的输出消息。 | Chat History。 | 历史 Assistant Message 不是 Current Truth。 |
| Chat Template | 把角色消息转换成模型实际 Token 序列的格式模板。 | 本地模型服务、不同模型兼容。 | Chat Template 不等于 Prompt 内容本身。 |
| Structured Output | 要求模型输出符合明确结构约束的数据。 | JSON、分类、Task Candidate。 | Structured Output ≠ Tool Calling。 |
| Inference（推理运行） | 用已训练模型处理输入并生成输出。 | 本地/云模型服务。 | Inference ≠ Training。 |
| Pre-training（预训练） | 在大规模数据上学习通用表示与生成能力。 | Foundation Model 形成。 | Pre-training ≠ SFT。 |
| Post-training（后训练） | 预训练后继续用指令、偏好、安全等信号塑造行为。 | Instruct/Reasoning 模型形成。 | Post-training 是总称。 |
| SFT | Supervised Fine-Tuning，用高质量输入输出样本做监督微调。 | 指令跟随、领域适配。 | SFT ≠ RLHF/DPO。 |
| Instruction Tuning | 用多任务指令数据提升模型遵循自然语言任务的能力。 | 从 Base 向 Instruct 演进。 | 通常属于后训练的一部分。 |
| Preference Data | 表示不同回答相对偏好的训练数据。 | RLHF、DPO。 | Preference 不等于事实标签。 |
| RLHF | 利用人类偏好训练奖励/策略以调整模型行为的路线。 | 对齐与交互质量优化。 | RLHF 是训练方法，不是 Runtime Guardrail。 |
| Reward Model | 学习“哪个输出更符合偏好”的评分模型。 | 经典 RLHF 流程。 | Reward Model ≠ Eval Judge，虽然都可能打分。 |
| DPO | 直接使用偏好对优化模型，无需显式在线强化学习循环的一类方法。 | 后训练对齐。 | DPO ≠ SFT。 |
| Alignment（对齐） | 让模型行为更符合目标、偏好与安全约束的训练和系统工程问题。 | 模型后训练与产品治理。 | 训练对齐不能替代 Runtime Permission。 |
| In-context Learning | 模型通过当前 Context 中的说明和示例临时适应任务。 | Few-shot、格式学习。 | 不修改模型参数。 |
| Zero-shot / One-shot / Few-shot | 分别用零个、一个、少量示例引导模型完成任务。 | Prompt 设计与能力评估。 | 示例数量不等于训练数据量。 |
| Reasoning Model | 针对复杂推理投入更多推理过程或训练优化的模型类别。 | 复杂规划、数学、代码。 | Reasoning Model 仍需要外部 Evidence 校验。 |
| Reasoning Effort / Budget | 控制推理投入程度的运行参数或资源预算。 | FAST/THINK 模式。 | 更高预算不保证更高事实正确率。 |
| Test-time Compute | 在推理阶段增加采样、搜索、验证等计算来提升结果质量。 | 复杂任务多候选/自检。 | 发生在推理期，不修改长期参数。 |
| MoE | Mixture of Experts，只激活部分专家网络处理每个 Token 的稀疏模型架构。 | 大模型扩展计算效率。 | 专家网络 ≠ Multi-Agent。 |
| Quantization（量化） | 降低模型权重/激活数值精度以减少内存和计算成本。 | 端侧模型、GPU/手机部署。 | 量化会影响性能和可能的质量。 |
| Multimodal Model / VLM | 同时处理文本、图像等多种模态的模型。 | 图片理解、视觉问答。 | 多模态能力 ≠ Computer Use 执行动作。 |
| On-device Model | 直接运行在用户设备上的模型。 | 手机模型、离线推理。 | 端侧优势是隐私/延迟/成本，能力仍受硬件约束。 |
| Cloud Model | 运行在远端云服务中的模型。 | 高能力推理、弹性服务。 | Cloud/On-device 是部署位置，不是能力等级本身。 |
| Serving | 把模型包装成可持续接收请求的推理服务。 | OpenAI-compatible API、本地模型 Server。 | Serving ≠ 单次 Inference。 |
| Batching | 把多个请求或 Token 批量计算以提升硬件利用率。 | 模型服务吞吐优化。 | 吞吐提升可能增加单请求等待。 |

## 这一层必须真正会区分

- **Process ≠ Task**：一个是操作系统执行实例，一个是业务工作对象。
- **Protocol ≠ API ≠ Schema**：分别回答“怎么交互”“暴露什么能力”“数据长什么样”。
- **Context Window ≠ Runtime Context**：前者是模型容量，后者是本轮实际工作集。
- **Base Model ≠ Instruct Model ≠ Agent**：训练阶段、模型产品形态、长期执行系统是三层。
- **Quantization ≠ Distillation ≠ Routing**：量化改数值精度，蒸馏改模型能力来源，路由决定当前用谁。
