# 智能体工程术语表

> 这不是 A-Z 技术词典，也不是“英文单词 + 中文翻译”的速查表。
>
> 术语真正学会以后，应该能回答：**它为什么出现、解决什么问题、在系统哪一层、什么时候会遇到、和谁容易混、出了问题从哪里查。**

当前版本以本知识库为唯一维护边界，不依赖其他项目的术语系统。术语范围覆盖现代 AI / Agent 工程主链；普通前端、数据库、Kubernetes 等通用工程词，只有在它是 Agent/RAG/Runtime/Platform 的必要前置时才进入。

## 什么叫“完整”

这里的“完整”不是收录所有技术名词，而是满足两条：

1. **主链完整**：从系统基础、模型、Context/RAG、Tool/MCP、Agent Runtime/Harness、Workflow/Multi-Agent、Durable Execution/Governance 到 Eval/Platform 没有断层；
2. **术语不是孤点**：每个正式术语至少有“一句话 + 场景 + 关键边界”，并能挂到一条真实工程关系链。

当前分层词表共收录 **520 个术语条目**（跨层相关词允许在必要位置重复出现，实际唯一词数略低）。这已经从“核心几十词”升级为一套可连续学习的 AI / Agent 工程术语地图。

## 学习深度

| 深度 | 你应该能做到什么 | 判断标准 |
|---|---|---|
| D0｜识别 | 知道词属于哪一层 | 看到 MCP 知道它是协议层，不是 Runtime |
| D1｜解释 | 用自己的话说清是什么、解决什么 | 不背字面翻译 |
| D2｜连接 | 说清前置、上下游、易混概念 | 能把 Tool Calling/MCP/Runtime 串起来 |
| D3｜应用 / Debug | 能放进真实系统并定位失败 | Timeout 后知道先看 Effect/Truth |
| D4｜设计 | 能做边界和取舍 | 知道何时用 Workflow、Subagent、Multi-Agent |

## 一条完整的 Agent 工程主链

~~~text
User Goal
↓
Task / Workflow
↓
State + Knowledge + Memory
↓
Context Engineering
↓
Harness
├── Instructions
├── Tool Surface
├── Workspace / Sandbox
├── Validator
└── Budget / Stop Rule
↓
Agent Runtime
↓
Model
↓
Tool Calling
↓
Tool / MCP / Adapter
↓
Real World
↓
Observation / Readback / Evidence
↓
Effect Verification / Truth Commit
↓
Checkpoint / Handoff / Recovery
↓
Eval / Observability / Routing
↓
Release / Business Outcome / Feedback Loop
~~~

这条链不是要求所有产品都一次性拥有所有层，而是帮助判断：**当前问题究竟属于模型、Context、Harness、Runtime、Tool、Workflow、Governance 还是 Platform。**

## 十二组必须真正会区分的关系

| 关系 | 最短记法 |
|---|---|
| Model / Agent / Runtime / Harness | Model 负责智能；Agent 做判断；Runtime 维持长期责任；Harness 组织当前工作环境 |
| Prompt / Context | Prompt 是表达；Context 是本轮完整工作集 |
| State / History / Memory / Context | 现在 / 过去 / 可复用过去 / 本轮需要看到 |
| Knowledge Source / Memory | 权威知识 / 经历型复用信息 |
| Embedding / Retrieval / Rerank / RAG | 表示 / 召回 / 重排 / 端到端检索增强 |
| Function Calling / Tool Calling / MCP | 函数调用机制 / 工具调用意图 / 标准接入协议 |
| Capability / Tool / Provider | 稳定能力语义 / 调用接口 / 外部实现方 |
| Task / Run / Session / Invocation | 长期工作 / 执行尝试 / 宿主会话 / 单次模型调用 |
| Workflow / Subagent / Multi-Agent | 受控路径 / 局部委派 / 多独立责任主体协作 |
| Permission / Policy / Approval | 原则上能不能 / 当前该不该 / 这一次有没有正式批准 |
| Timeout / UNKNOWN / FAILED | 没按时得到结果 / 证据不足 / 已证明失败 |
| Eval / Acceptance / Release | 系统质量 / 当前交付 Gate / 正式交付 |

## 怎样使用这份术语表

第一次学习不要随机查词。建议按：

~~~text
基础与模型
→ Context / RAG
→ Tool / MCP
→ Agent Runtime / Harness
→ Workflow / Multi-Agent
→ Recovery / Governance
→ Eval / Platform
~~~

遇到真实问题则反向使用：

~~~text
“模型回答错了”
→ 是 Model 能力？
→ Context 不对？
→ Retrieval 没找对？
→ Harness 暴露错 Tool？
→ Runtime State 过期？
→ Eval 标准本身有问题？
~~~

术语的价值就在这里：它帮助你找到**正确的问题层级**，而不是只增加词汇量。

## 收录边界

明确收录：
- 现代模型与推理的必要基础；
- Context / Memory / RAG / Knowledge；
- Tool Calling、MCP、Capability、Adapter；
- Agent、Runtime、Harness、Workflow；
- Subagent、Multi-Agent、A2A；
- Durable Execution、Recovery、Permission、Policy、Approval；
- Eval、Observability、Routing、Platform。

默认不全量收录：
- 普通前端框架 API；
- 通用数据库内部实现；
- 通用 Kubernetes 命令与对象；
- 某个 Provider 的短期产品按钮或私有参数；
- 只在历史项目里出现、没有长期概念价值的内部状态名。

这些内容只有在它成为 AI / Agent 主链的必要前置时才进入。

## 维护原则

1. **先找层级，再加词。** 新词必须先挂到现有主链。
2. **至少四维。** 正式词条至少有定义、场景、系统位置/关系、易混边界。
3. **基础词和核心词深度不同。** D0-D2 足以支撑普通前置；关键 Agent 工程词继续扩到 D3-D4。
4. **协议和产品事实会变化。** MCP、模型 API、Provider 参数等使用时重新核验当前版本。
5. **不制造第二真源。** 项目当前状态继续由项目自己的 Spec、Runtime、Git 或 Task Store 拥有；术语表只拥有概念语义。
